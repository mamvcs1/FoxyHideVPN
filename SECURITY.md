# Security Policy

## Supported versions

Only the latest published release is supported with security fixes. Please
update to the latest release before reporting an issue.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in public issues, discussions,
or pull requests.

Use GitHub's **Report a vulnerability** feature in the repository's Security
tab to send a private report when it is enabled. Include the affected version,
platform, impact, reproduction steps, and any relevant logs with credentials,
tokens, IP addresses, and other personal data removed.

If private vulnerability reporting is unavailable, contact the repository
maintainer through the contact method listed on the maintainer's GitHub profile.
Allow reasonable time for triage and a fix before public disclosure.

## Scope

Reports involving authentication bypass, credential or token exposure, traffic
leaks, unsafe update installation, privilege escalation, remote code execution,
and denial of service are especially important.

Do not test against systems, accounts, or infrastructure you do not own or
have explicit permission to assess.
